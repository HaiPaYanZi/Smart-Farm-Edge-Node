## 1. 测试目的

验证系统满足需求规格书的全部功能需求、性能指标与安全需求，形成可追溯的测试证据。

## 2. 测试范围

### 2.1 在测范围
- 固件全部功能（采集/控制/模式/规则/存储/通信/OTA/显示/报警）
- 性能指标（采集周期/控制周期/PID 精度/Modbus 响应/断网自治/恢复时间）
- 安全与故障处理（故障注入）
- 底板自研电路（电源/485/驱动/蜂鸣器）

### 2.2 不在测范围
- 核心板本体（厂商已验证）
- 传感器模块精度溯源（比对参考仪表，非计量校准）
- GEC6818 上层功能（仅联调贯通性测试，见联调指导书）

## 3. 测试环境

| 项 | 配置 |
|---|---|
| 被测件 | STM32F103RCT6 网关（模块平台 → 底板） |
| 上位机 | Windows + ModbusPoll（或自写 Python 工具） |
| 调试工具 | ST-Link、USB转RS485、逻辑分析仪（16M）、万用表、示波器 |
| 测试辅助 | 恒温水槽/热风枪（温度场景）、堵转道具（手刹风机）、可调电源（掉电测试） |
| 比对仪表 | 水银温度计/校准温湿度计 |

## 4. 测试策略

| 测试类型 | 方法 | 对应用例 |
|---|---|---|
| 功能测试 | 逐项验证 FR1~FR9 | F 系列 |
| 边界测试 | 量程两端/满量程/极限参数 | B 系列 |
| 异常测试 | 故障注入（拔传感器/堵转/断线/断电） | E 系列 |
| 可靠性测试 | 24h 连续跑机 + 循环断电 | R 系列 |
| 硬件测试 | 自研电路电压/波形/发热 | H 系列 |
| 回归测试 | 每次固件发布前跑 F 系列全量 + E 系列关键项 | - |

**执行顺序**：H（硬件可用）→ F（功能）→ B（边界）→ E（异常）→ R（可靠）。

## 5. 测试进度安排

| 阶段 | 时间 | 内容 |
|---|---|---|
| 模块平台 | 第 2~3 周 | F 系列大部分 + H 系列洞洞板验证 |
| 底板平台 | 第 4 周初 | H 系列全量 + B/E 系列 |
| 联调期 | 第 4 周 | GEC6818 贯通 + R 系列 |
| 发布前 | 第 4 周末 | 全量回归 + 报告归档 |

## 6. 缺陷管理

| 项 | 规则 |
|---|---|
| 缺陷等级 | A 致命（死机/数据丢失/设备损坏）/ B 严重（功能不可用）/ C 一般 / D 建议 |
| 记录 | 测试报告（D2）中登记：编号/描述/复现步骤/等级/状态 |
| 修复流程 | A/B 级缺陷必须修复后回归通过才允许发布 |
| 回归 | 修复后跑关联用例 + 全量 F 系列 |

## 7. 测试通过准则

1. F 系列通过率 100%（无 A/B 级未闭环缺陷）；
2. 性能指标 PERF1~10 全部达标；
3. SAF1~8 全部故障注入通过；
4. 24h 跑机无死机、无日志丢失；
5. 底板 H 系列全项通过（含满载温升）。

## 8. 测试记录存放

- 测试数据文件：`docs/testdata/`（跑机日志、曲线截图、波形抓拍）；
- 结果归档：`10-测试用例与报告.md` 更新至 V1.x 并提交 git。
