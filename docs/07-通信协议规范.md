## 1. 协议分层

```
应用层: 固件文件/版本/校验逻辑
传输层: 本协议帧（分包/序号/应答/重传）
物理层: RS485(9600) 或 USB转串口(115200) 或 GEC6818 中转
```

**通道选择**（优先级从高到低）：
1. PC 直连（USB转RS485 → 网关）：开发/演示主力通道；
2. GEC6818 中转：PC → TCP → GEC6818 → RS485 → 网关（联调阶段加分项，机制相同）；
3. 升级时应用不再响应 Modbus（Boot 阶段运行，应用未启动），需在升级前通知上联。

## 2. 帧格式（统一帧结构）

```
┌──────┬──────┬────────┬────────┬────────┬──────────┬──────────┬────────┐
│ 帧头  │ 帧头  │ 命令   │ 序列号  │ 长度   │  数据域   │  CRC16   │ 帧尾   │
│ 0xAA  │ 0x55  │ 1B    │ 2B    │ 2B    │  N B     │  2B      │ 0x0D   │
└──────┴──────┴────────┴────────┴────────┴──────────┴──────────┴────────┘
```

| 字段 | 长度 | 说明 |
|---|---|---|
| 帧头 | 2B | 固定 0xAA 0x55 |
| 命令 | 1B | 见 §3 |
| 序列号 | 2B | 每帧递增（数据包用）；应答回显原序列号 |
| 长度 | 2B | 数据域字节数（0~512） |
| 数据域 | N B | 命令相关 |
| CRC16 | 2B | CRC16-MODBUS，覆盖"命令~数据域" |
| 帧尾 | 1B | 固定 0x0D |

**收帧处理**：按帧头+长度收满 N+10 字节 → 校验 CRC → 校验帧尾 → 应答。非法帧丢弃并计数（连续 10 帧非法 → 重新握手）。

## 3. 命令集

### 3.1 握手

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x01 | 固件版本(2B) | 询问设备状态 |
| 设备→主机 | 0x81 | 状态(1B) + 当前版本(2B) + 分区(1B) | 状态: 0x00 就绪 0x01 忙 0x02 已在升级 |

### 3.2 开始传输

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x02 | 固件头(16B，见 CM 文档) | 宣告本次升级 |
| 设备→主机 | 0x82 | 结果(1B) | 0x00 接受 0x01 版本过低拒绝 0x02 分区无效 0x03 长度超限 |

### 3.3 数据包

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x03 | 包号(2B) + 数据(N B, ≤256) | 按序传输 |
| 设备→主机 | 0x83 | 包号(2B) + 结果(1B) | 0x00 成功，0x01 校验失败(重传) |

- 每包数据必须写满 256B（最后一包除外，以固件长度为准）；
- 设备收到包 → 校验 CRC → 写 B 区缓存 → 应答成功；
- **连续 3 包无应答/超时** → 主机暂停重发当前包，3 次后判定设备离线，升级失败；
- 设备侧：收包 5s 无新包 → 丢弃本次升级，回滚到原分区运行。

### 3.4 传输结束与校验

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x04 | 包数(2B) | 告知总包数 |
| 设备→主机 | 0x84 | 包数(2B) | 确认收包数；不一致→主机从缺失包续传 |
| 主机→设备 | 0x05 | CRC32(4B) | 请求全片校验 |
| 设备→主机 | 0x85 | 结果(1B) | 0x00 通过 0x01 不通过(重传失败段) |

### 3.5 执行升级

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x06 | 目标分区(1B) | 0x01=A 0x02=B（当前运行 B 则升 A） |
| 设备→主机 | 0x86 | 结果(1B) | 0x00 已接受，即将重启 |

- 设备回 0x00 → 写分区有效标志 → 软复位；
- Boot 校验新分区 → 有效则跳转，无效/超时 → **回滚原分区**并置故障码 0x0302。

### 3.6 查询进度（可选，GEC6818 中转时用）

| 方向 | 命令 | 数据域 | 说明 |
|---|---|---|---|
| 主机→设备 | 0x07 | - | 查询 |
| 设备→主机 | 0x87 | 已收包数(2B)/总包数(2B) | 进度 = 已收/总 |

## 4. 升级流程（时序）

```
PC工具 ──握手(0x01)──────────────────────────→ 设备(版本/分区)
PC工具 ──开始传输(0x02+固件头)───────────────→ 设备(接受)
循环:  PC工具 ──数据包(0x03+包号+256B)──────→ 设备(0x83 成功)
PC工具 ──结束(0x04) ──校验(0x05+CRC32)──────→ 设备(0x85 通过)
PC工具 ──执行(0x06) ────────────────────────→ 设备(0x86) → 软复位
Boot: 校验新分区 → 跳转新分区 → 新版本启动
失败路径: 任一步超时/校验失败 → 设备保持原分区运行，故障码上报
```

## 5. Bootloader 与分区布局

| 分区 | 地址 | 大小 | 内容 |
|---|---|---|---|
| Bootloader | 0x08000000 | 8KB（2 页） | 升级流程 + 跳转 |
| 参数区 | 0x08002000 | 2 页（双页轮换） | 运行参数 |
| 升级标志 | 0x08003000 | 1 页 | 升级状态/版本记录 |
| App A | 0x08010000 | 100KB | 当前运行（默认） |
| App B | 0x08020000 | 100KB | 升级目标 |

> F103 页大小 1KB；App 编译时 IROM1 起始必须与分区地址一致（A: 0x08010000，B: 0x08020000）。

**Boot 跳转要点**：
1. 关闭全局中断、复位所有外设；
2. `SCB->VTOR = APP_BASE`（0x08010000）；
3. 取新向量表 `SP = *(uint32_t*)APP_BASE`，`PC = *(uint32_t*)(APP_BASE+4)`；
4. 设置 MSP 后跳转。

## 7. GEC6818 中转模式（联调阶段）

```
PC(升级工具) ──TCP 9001──→ GEC6818(转发程序) ──RS485(9600)──→ 网关
```

- GEC6818 转发程序：接收 TCP 字节流 → 原样转发到 RS485 串口，返回路径反向；
- 协议与直连完全一致（帧结构不变），仅物理通道不同；
- 升级期间 GEC6818 暂停 Modbus 轮询该从站（避免应答冲突）。
