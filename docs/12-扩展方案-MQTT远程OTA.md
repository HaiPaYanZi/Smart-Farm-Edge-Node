| 定位 | 在主线(RS485/Modbus → GEC6818 → HMI)之外,为节点增加 WiFi 上云能力:传感器数据发布到 MQTT broker、远程控制命令下发、固件远程升级 |

> 执行原则:本扩展**依赖主线 1.7 的 bootloader 双分区机制**(通道无关),
> bootloader 是远程 OTA 的地基,扩展只替换/增加"固件传输通道"。

---

## 1. 背景与目标

主线采用 RS485/Modbus 上联,适合工业现场,但远程运维受限。扩展目标:

- **远程监控**:传感器数据(温度/湿度/光照/土壤/转速)通过 MQTT 发布到云平台,手机/PC 随时查看
- **远程控制**:MQTT 订阅命令,远程开关水泵/补光、修改阈值(复用规则引擎)
- **远程 OTA**:固件通过 WiFi 下发,双分区升级 + 断电回滚

## 2. 扩展架构

```
STM32F103 节点
   ├── USART3 ── RS485/Modbus ──→ GEC6818 网关 ──→ HMI(主线,不变)
   ├── USART1 ── CH340 ──→ PC 调试口(主线,不变)
   └── USART2 ── ESP8266(AT 透传)── WiFi ──→ MQTT broker ──→ 手机/PC/云
         ↑ 扩展:新增
```

### 2.1 硬件规划

| 项 | 方案 | 说明 |
|---|---|---|
| WiFi 模块 | ESP8266-01S / ESP-12F(AT 固件) | 最便宜、资料最多 |
| 挂载串口 | USART2(PA2/PA3) | 当前为"底板期调试口"(04 文档),扩展期二选一:调试口或 ESP8266 |
| 供电 | 3.3V/300mA(ESP8266 峰值电流大,须独立 LDO 或模块供电) | 不能直接吃板载 3.3V 小电流 |
| 电平 | 3.3V 兼容,直连 | - |

### 2.2 数据映射(复用 modbus_reg 的数据组织)

| MQTT 主题 | 方向 | 内容 | 数据来源 |
|---|---|---|---|
| `agri/node4/data` | 发布(500ms~1s) | JSON:温度/湿度/光照/土壤/转速/占空比/状态字 | `modbus_reg.c` 30001~30007 同一套数据 |
| `agri/node4/cmd` | 订阅 | JSON 命令:开泵/开灯/设阈值/重启 | 复用 `g_rules` 写逻辑(同 40008~40011) |
| `agri/node4/fw` | 订阅 | 固件分包(序号+数据+CRC) | 远程 OTA 专用 |

> 设计要点:扩展层**不重造数据**,直接复用 Modbus 寄存器表的数据组织和规则引擎写阈值逻辑——主线工作零浪费。

## 3. 远程 OTA 设计(依赖主线 1.7)

### 3.1 分区布局(与主线 1.7 一致,通道无关)

```
0x08000000  Bootloader   16KB   (跳转 + 升级协议)
0x08004000  App A       112KB   (当前运行)
0x0801C000  App B       112KB   (升级目标)
0x08038000  参数区/预留  16KB
```

### 3.2 升级流程(远程版)

```
① 云平台下发新固件 → MQTT 分包(每包 N 字节 + 包序号 + CRC16)
② 节点 App 收到完整固件 → 校验总 CRC → 写标志位"待升级" → 跳转 bootloader
   (或 bootloader 直接收包,视实现而定)
③ Bootloader 擦写 B 区 → 逐包写入 → 校验 → 跳转 B 区
④ 新固件起不来(看门狗)→ 回滚 A 区;坏固件拒绝启动
```

### 3.3 安全措施

- 固件包 CRC32/双校验,坏包拒绝
- 升级中断(断电)可恢复:标志位 + 看门狗双保险
- 回滚:失败自动回 A 区,最多 N 次重试

## 4. 实施阶段(扩展线,穿插主线之后)

| 阶段 | 内容 | 前置 | 产出 |
|---|---|---|---|
| 阶段 0 | **主线 1.7 bootloader**(串口/485 验证) | 1.6 完成 | 双分区 + 回滚可用 |
| 阶段 1 | ESP8266 AT 透传:USART2 驱动 + AT 指令框架 | 模块到货 | 串口 → WiFi 数据链路 |
| 阶段 2 | MQTT 发布/订阅:连接 broker、JSON 组包/解析、重连机制 | 阶段 1 | 数据上云 + 远程控制 |
| 阶段 3 | 远程 OTA:固件分包传输 + bootloader 对接 | 阶段 0 + 2 | 远程升级闭环 |

## 5. 风险与注意

| 风险 | 对策 |
|---|---|
| 温室 WiFi 不稳定 | MQTT QoS1 + 自动重连 + 断网自治(主线已有:规则引擎本地运行 ≥24h) |
| ESP8266 峰值电流 | 独立 3.3V 供电,不拖垮节点 |
| 安全(固件被篡改) | 升级包签名/密钥(可选,按需) |
| USART2 与调试口冲突 | 扩展期放弃 USART2 调试,保留 USART1(CH340) |
