## 2. Git 规范

### 2.1 分支策略（个人项目简化版）

```
main（主分支，永远可编译可运行）
 └── dev（开发分支，日常提交都在这里）
      └── feature/xxx（功能分支，完成后合并 dev）
tag: v1.0.0 / v1.1.0 ...（对应发布版本，与固件版本一致）
```

- main 只接受 dev 的合并请求；
- 合并前保证：编译通过 + 冒烟测试通过；
- 禁止直接向 main 提交。

### 2.2 Commit 规范

| 前缀 | 用途 | 示例 |
|---|---|---|
| `feat:` | 新功能 | `feat: 实现温度PID闭环控制` |
| `fix:` | 缺陷修复 | `fix: 修复粘包导致帧解析错位` |
| `docs:` | 文档 | `docs: 更新Modbus寄存器表` |
| `refactor:` | 重构 | `refactor: 采集任务改双缓冲` |
| `test:` | 测试 | `test: 增加堵转用例` |
| `chore:` | 杂项 | `chore: 升级FreeRTOS版本` |

格式：`<type>: <中文描述>（关联编号可选）`，一条 commit 只做一件事。

### 2.3 提交频率

- 每个模块完成一个可编译单元即提交；
- 每天至少一次提交（保证可回退）；
- 调通一个功能点立刻提交（防止调试把代码改坏找不回）。

## 3. 固件版本管理（与 OTA 联动）

### 3.1 版本号规范（语义化）

```
V<主>.<次>.<补丁>   例: V1.2.3
主版本：架构/协议不兼容变更（寄存器表变更、分区变更）
次版本：新增功能（新规则、新寄存器）
补丁：  缺陷修复、参数调整
```

### 3.2 固件头格式（Boot/App 共用，shared 目录定义）

```c
typedef struct __attribute__((packed)) {
    uint32_t magic;      // 0x4D4F4749 "GWNM"
    uint8_t  major;      // 主版本
    uint8_t  minor;      // 次版本
    uint8_t  patch;      // 补丁
    uint8_t  flags;      // bit0: A区有效 bit1: B区有效
    uint32_t length;     // 固件长度(不含头)
    uint32_t crc32;      // 固件数据 CRC32
} firmware_header_t;     // 16 字节，放分区起始地址
```

> 勘误 V1.1（2026-08-15）：① 实现中结构体名 `ota_fw_header_t`（shared/ota_common.h），
> 用 `#pragma pack(push,1)` 对齐（与 `__attribute__((packed))` 等价）；
> ② flags 字段保留为 0（分区有效性由升级标志区 active_part 管理）；
> ③ 头放分区起始后，App 向量表后移 0x200，IROM1=分区+0x200（A: 0x08010200）。

### 3.3 版本变更流程

1. 修改代码 → 更新 `version.h`（宏定义版本号）→ 更新 `CHANGELOG.md`；
2. 编译 App → 生成 `app_v1.1.0.bin`；
3. 通过 OTA 工具传输 → 目标升级成功后打 git tag `v1.1.0`；
4. **禁止跳版本发布**（如 v1.0 → v1.2），版本号必须连续。

### 3.4 CHANGELOG 模板

```markdown
## [V1.1.0] - 2026-08-15

- 补光规则可远程配置阈值（寄存器 40008）
```

## 5. CubeMX 重新生成后的手动同步清单（重点！）

> 适用：每次在 CubeMX 里改引脚/外设后"重新生成代码"。
> CubeMX 机制：**USER CODE 区内代码原样保留**；**.ioc 管的配置按 .ioc 重新生成**；
> **但以下"手改项"不在 .ioc 里，重生成会丢/变回默认——逐项核对！**

### 5.1 必须手动重设/核对的项（重生成会丢）

| # | 项 | 正确值 | 位置 | 丢了会怎样 |
|---|---|---|---|---|
| 1 | **App IROM1 基址**（OTA 双分区核心） | Start=0x10200, Size=0x18E00 | Keil Options→Target→IROM1（sct 是自动生成的，源头在这里） | 重置为 0x08000000 → 与 Boot 区重叠，双分区全废，烧录即坏 |
| 2 | **USART3 中断接管**（Modbus 核心） | 注释掉 `HAL_UART_IRQHandler(&huart3);`，改调 `vMBPortSerialISR();` | stm32f1xx_it.c 的 USART3_IRQHandler | HAL 吞掉 RXNE 字节 → Modbus 收不到帧（vMBPortSerialISR 调用在 USER CODE 区会保留，但注释掉的生成行会恢复，需再次注释） |
| 3 | **Keil 工程自定义源码组** | App / Bsp / Divece / FreeModbus / Port 5 个组及文件 | uvprojx（Options→Target 的组结构） | 器件驱动/协议栈源码脱离工程 → 编译报"未定义" |
| 4 | **Keil include 路径自定义段** | `./app;./Bsp;./Divece;./FreeModbus` 等 | Options→C/C++→Include Paths | 头文件找不到 → 编译报错 |
| 5 | **ffconf.h 三项手改**（FatFs） | `_USE_WRITE`=1、`_USE_IOCTL`=1、`_FS_REENTRANT`=0 | FATFS/Target/ffconf.h | CubeMX 按默认覆盖（0/0/1）→ f_write 链接错误、ioctl 失效、syscall.c(CMSIS v1) 与 FreeRTOS v2 冲突编译报错 |

### 5.2 .ioc 已同步、重生成自动正确的项（知道即可，不用动）

| 项 | 说明 |
|---|---|
| 栈大小 | .ioc `ProjectManager.StackSize=0x800` → startup 自动 0x800（**main.c 宏 STACK_SIZE_BYTES=2048 需人工核对一致**） |
| PB14 上拉（SPI2 MISO，SD 卡） | spi.c MspInit 生成区显示 GPIO_PULLUP，.ioc 已同步 |
| USART3 9600 / TIM2 3.5T / NVIC 优先级 | .ioc 管，重生成跟随 |
| 编译宏 USE_HAL_DRIVER,STM32F103xE | CubeMX 标准宏 |

### 5.3 USER CODE 区内改动（重生成保留，核对即可）

| 文件 | 内容 |
|---|---|
| main.c | 栈金丝雀全套（PD/PV/PFP/BEGIN1/2/4）+ HAL_TIM_PeriodElapsedCallback（Modbus 3.5T 回调）。注：向量表 VTOR 不再由 App 设——Boot 跳转前设置（2026-08-19 修复，详见 main.c BEGIN 1 注释） |
| freertos.c | 各任务/互斥锁/事件 + stack_overflow_check 周期调用 + vApplicationStackOverflowHook |
| stm32f1xx_it.c | vMBPortSerialISR 外部声明 + USART3 ISR 区注释说明 |
| usart.c | printf 重定向 fputc/_write（BEGIN 1，USART1 调试口） |

### 5.4 独立文件（CubeMX 完全不碰）

- `MDK-ARM/App/`：version.h（版本号）；`MDK-ARM/Bsp/`、`Divece/`：器件驱动；`MDK-ARM/FreeModbus/` + Port 组：协议栈与移植；`shared/`：ota_common.h 分区表；`pc_tool/`：上位机工具；`Boot/`：独立 Bootloader 工程
- `FATFS/Target/user_diskio.c`：SD 对接代码全部在 USER CODE 区（已核实），重生成保留，**无需恢复**
- TIM4：HAL 心跳时间基（stm32f1xx_hal_timebase_tim.c 的 htim4），**不能挪作他用**

### 5.5 重生成后的验证三步（必做）

1. **重新编译**：Boot + App 两个工程 0 Error 0 Warning；
2. **看 MAP**：STACK 段 2048B、`__initial_sp` 在栈顶、ER_IROM1 基址 = 0x08010200（App）；
3. **烧录冒烟**：启动日志正常 → **Modbus 轮询收发正常**（验证 USART3 接管）→ **OTA 升级链路走一遍**（`part X valid, fail=00 00`）。

### 5.6 其他纪律

- 所有自定义代码**必须放 USER CODE BEGIN/END 区内**——区外改动重生成必丢（stm32f1xx_it.c 的 USART3 注释是当前唯一已知的区外手改，已列在 5.1）；
- 手改过任何生成文件，改完立即登记到本节，并预期重生成后需重改；
- Boot 工程独立手写（Boot/），不受 CubeMX 影响。
