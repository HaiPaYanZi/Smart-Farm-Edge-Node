## 2. Git 规范

### 2.1 分支策略（个人项目简化版）

```
main（主分支，永远可编译可运行）
 └── dev（开发分支，日常提交都在这里）
      └── feature/xxx（功能分支，完成后合并 dev）
tag: v1.0.0 / v1.1.0 ...（对应发布版本，与固件版本一致）
```

- main 只接受 dev 的合并请求；
- 合并前保证：编译通过 + 冒烟测试通过；
- 禁止直接向 main 提交。

### 2.2 Commit 规范

| 前缀 | 用途 | 示例 |
|---|---|---|
| `feat:` | 新功能 | `feat: 实现温度PID闭环控制` |
| `fix:` | 缺陷修复 | `fix: 修复粘包导致帧解析错位` |
| `docs:` | 文档 | `docs: 更新Modbus寄存器表` |
| `refactor:` | 重构 | `refactor: 采集任务改双缓冲` |
| `test:` | 测试 | `test: 增加堵转用例` |
| `chore:` | 杂项 | `chore: 升级FreeRTOS版本` |

格式：`<type>: <中文描述>（关联编号可选）`，一条 commit 只做一件事。

### 2.3 提交频率

- 每个模块完成一个可编译单元即提交；
- 每天至少一次提交（保证可回退）；
- 调通一个功能点立刻提交（防止调试把代码改坏找不回）。

## 3. 固件版本管理（与 OTA 联动）

### 3.1 版本号规范（语义化）

```
V<主>.<次>.<补丁>   例: V1.2.3
主版本：架构/协议不兼容变更（寄存器表变更、分区变更）
次版本：新增功能（新规则、新寄存器）
补丁：  缺陷修复、参数调整
```

### 3.2 固件头格式（Boot/App 共用，shared 目录定义）

```c
typedef struct __attribute__((packed)) {
    uint32_t magic;      // 0x4D4F4749 "GWNM"
    uint8_t  major;      // 主版本
    uint8_t  minor;      // 次版本
    uint8_t  patch;      // 补丁
    uint8_t  flags;      // bit0: A区有效 bit1: B区有效
    uint32_t length;     // 固件长度(不含头)
    uint32_t crc32;      // 固件数据 CRC32
} firmware_header_t;     // 16 字节，放分区起始地址
```

### 3.3 版本变更流程

1. 修改代码 → 更新 `version.h`（宏定义版本号）→ 更新 `CHANGELOG.md`；
2. 编译 App → 生成 `app_v1.1.0.bin`；
3. 通过 OTA 工具传输 → 目标升级成功后打 git tag `v1.1.0`；
4. **禁止跳版本发布**（如 v1.0 → v1.2），版本号必须连续。

### 3.4 CHANGELOG 模板

```markdown
## [V1.1.0] - 2026-08-15
### 新增
- 补光规则可远程配置阈值（寄存器 40008）
### 修复
- 修复 RS485 DE 引脚时序导致的偶发乱帧
### 变更
- PID 默认参数调整（Kp 8.0）
```

| 配置项 | 存放位置 | 管理方式 |
