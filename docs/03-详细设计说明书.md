## 2. PID 控制器设计（核心模块）

### 2.1 算法选择：位置式 PID + 抗积分饱和

```
u(k) = Kp·e(k) + Ki·Σe(i) + Kd·[e(k) - e(k-1)]
其中 e(k) = 目标温度 - 当前温度
输出 u(k) 限幅至 [0, 100]（%占空比）
```

### 2.2 实现要点

| 要点 | 实现 |
|---|---|
| 抗积分饱和 | 输出饱和（u=100 或 u=0）时，积分项停止累加（clamping 法） |
| 输出限幅 | 0~100%，双限幅 |
| 微分滤波（可选） | 对 e 做一阶低通（α=0.2）抑制噪声微分放大 |
| 整定方式 | 试凑法：先 P 后 I 再 D；现场演示"调 P 看风机抖动" |
| 采样/控制周期 | 控制任务 100ms 周期调用；与采集 200ms 解耦（PID 用最新快照） |
| 参数存储 | Kp: 0.1~50.0（默认 8.0）、Ki: 0.01~5.0（默认 0.3）、Kd: 0.1~20.0（默认 2.0），存 Flash，可远程改 |

### 2.3 数据结构

```c
typedef struct {
    float kp, ki, kd;
    float target;        // 目标温度(℃)
    float integral;      // 积分累加
    float prev_err;      // 上次误差(用于微分)
    float out;           // 输出 0~100
    float out_min, out_max; // 限幅(0,100)
    uint8_t  enabled;    // 使能
} pid_ctrl_t;
```

### 2.4 接口

```c
void pid_init(pid_ctrl_t *p, float kp, float ki, float kd);
float pid_update(pid_ctrl_t *p, float target, float feedback);
void pid_reset(pid_ctrl_t *p);   // 清积分(模式切换/参数变更时调用)
```

## 3. 规则引擎设计

### 3.1 规则表结构（周期 500ms 评估，控制任务内）

```c
typedef struct {
    uint16_t sensor_id;      // 输入源: SENSOR_TEMP/HUMI/LIGHT/SOIL
    float    threshold_hi;   // 上限阈值
    float    threshold_lo;   // 下限阈值
    float    hysteresis;     // 回差
    uint8_t  actuator_id;    // 执行器: ACT_FAN/ACT_LIGHT/ACT_PUMP
    uint8_t  action_hi;      // 高于上限的动作: 0无/1开/2关
    uint8_t  action_lo;      // 低于下限的动作
    uint8_t  mode;           // 0=禁用 1=使能(自动)
} rule_t;
```

### 3.2 预置规则（可在 Flash 中修改）

| 规则 | 输入 | 逻辑 | 执行器 |
|---|---|---|---|
| R1 通风（PID） | 温度 | PID 连续调节，滞回下限：温度<目标-2℃ 停转 | 风机 |
| R2 补光 | 光照 | <2000lx 开；>3000lx 关（回差 1000） | 补光灯 |
| R3 灌溉 | 土壤湿度 | <30% 开；>45% 关（回差 15） | 水泵 |

### 3.3 执行器输出映射

| 执行器 | 输出方式 | 手动模式替代 |
|---|---|---|
| 风机 | PID 输出 → 占空比 | 40006 直接写占空比 |
| 补光灯 | 规则开/关 → 占空比 80% 或 0% | 线圈 00002 |
| 水泵 | 规则开/关 → GPIO | 线圈 00001 |

## 4. 堵转检测与故障管理

### 4.1 堵转检测逻辑（反馈任务 + 控制任务协作）

```
状态: NORMAL → 输出占空比>30% → 启动检测窗口(3s)
      3s 内累计霍尔脉冲 < 阈值(如 5 个) → 判定堵转
      → FAULT(堵转): 停机(占空比0) + 蜂鸣器报警 + Modbus 状态位置位
      → 10s 后自动重试: 重新启动 → 再堵转 → FAULT(严重) → 停止自动重试
```

### 4.2 传感器失效判定

- 软件 I2C 读取失败连续 5 次（≈1s）→ 该传感器标记失效；
- 温度传感器失效 → 进入安全态：风机 30% 固定占空比（SAF2 哲学）；
- 光照/土壤失效 → 对应规则禁用，其余继续运行（降级）；
- 全部传感器失效 → FAULT(致命) → 复位进待机。

### 4.3 故障等级与状态字（上报 Modbus 30007）

```
bit0: 模式自动  bit1: 模式手动  bit2: 待机  bit3: 故障中  bit4: 恢复中
bit5: 堵转     bit6: 传感器失效  bit7: 上联断线  bit8: SD失败
```

## 5. Modbus 从机设计（FreeModbus 移植要点）

### 5.1 移植要点

- `eMBInit(MB_RTU, addr, 0, 9600, MB_PAR_NONE)`；
- RS485 DE 方向控制：UART TX 完成回调中置位/清零 DE（PA8）；
- `eMBPoll()` 放 Modbus 任务主循环，周期 ≥1ms；
- 保持寄存器/输入寄存器数组：`usRegHoldingBuf[16]`、`usRegInputBuf[8]`，读写回调里同步快照/参数区（互斥量保护）；
- **写回调中禁止执行耗时操作**：只更新参数区标志，实际生效由控制任务下次周期加载。

### 5.2 寄存器读写回调

```c
eMBErrorCode eMBRegHoldingCB(UCHAR *pucRegBuffer, USHORT usAddress,
                             USHORT usNRegs, eMBRegisterMode eMode);
// usAddress 为 0 基偏移，对应寄存器表 C1 文档
```

## 6. 数据存储设计

### 6.1 参数区（内部 Flash，模拟 NVS）

```
Flash 页4 (0x0800F000) 参数区1  | 页5 参数区2  ← 双页轮换，防掉电写坏
布局: 头(magic 0xA5A5 + crc16 + version) + 参数结构体
参数结构体: PID×3 + 目标温度 + 各阈值/回差 + 模式 + 从站地址 + 版本号
```

写策略：Modbus 修改参数 → 置 dirty 标志 → 控制任务空闲时批量写，写前关中断。

### 6.2 SD 卡日志格式（CSV，按天分文件）

```
2026-07-31.csv
时间戳,温度,湿度,光照,土壤,实际转速,目标转速,模式,状态字,事件
2026-07-31 14:00:01,28.4,65.2,3200,41,1200,1500,AUTO,0x0000,-
2026-07-31 14:00:05,28.9,64.8,3210,40,1500,1500,AUTO,0x0020,FAN_STALL
```

- 写入：日志队列攒 16 条 → 一次性 f_write；
- 滚动：单文件 >512KB 时新建当天第 2 个文件。

## 8. OTA 升级详细设计（见 C2 协议，此处为应用侧流程）

```
应用收到"升级指令"(40011=0x5A5A) → 校验固件头 → 置升级标志 → 软复位
Boot: 查标志 → 走升级流程 → 收分包写B区(1KB页) → CRC校验 → 切标志 → 跳转
失败路径: 收包超时/校验失败 → 保持A区 → 上报失败原因 → 恢复运行
```
